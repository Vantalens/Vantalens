## 核心项目

### [CodePanion](https://github.com/Vantalens/CodePanion)

CodePanion 是一个本地优先、供应商中立的多任务操作平台，面向开发者在本机同时使用多个 AI 编程工具、终端窗口与项目工作区的场景。

项目目标是将分散在 VS Code、终端、Codex、Claude Code、OpenCode 及其他本地工具中的任务状态统一汇聚到一个图形工作台中，帮助用户识别等待输入、执行失败、审阅需求与任务完成等关键状态，降低多任务并行开发中的上下文切换成本与阻塞遗漏风险。

核心能力：

- 多来源任务状态汇聚与统一展示
- 基于 `等待我 / 失败 / 需审阅 / 运行中 / 完成` 的任务队列组织
- 面向 AI 编程任务的阻塞点识别、状态恢复与上下文整理
- 标准化任务转交包生成，支持 Codex、Claude Code、OpenCode 等工具场景
- GUI 与本地 daemon 协同，支持本地状态持久化与重启恢复
- 强调本地优先、工具中立、隐私边界清晰的产品设计

技术形态：

- Windows GUI：WPF + WebView2
- 本地 daemon：Node.js
- 接入方式：CLI / PTTY / 本地适配器 / VS Code 来源事件等
- 数据策略：默认本地保存，不依赖全局屏幕读取、私有插件数据库或敏感凭据

该项目是我对 AI 工程工具与真实开发流程结合方式的一次系统化实践，重点不在于替代某个 AI 编程工具，而在于设计一个能够管理任务流、状态流与责任边界的上层工作台。

### Trans2Former

Trans2Former 是一个浏览器端文档转换与重构引擎，目标是围绕统一的 `DocumentModel`，对不同来源和格式的文档内容进行解析、转换、结构化表达与复用。

项目关注如何将非结构化或半结构化内容转换为更稳定、可处理、可展示的数据结构，并在前端环境中完成文档解析、内容重构与模型抽象。

主要关注点：

- 文档解析与内容转换
- 统一数据模型设计
- 半结构化内容的结构化表达
- 前端侧处理能力与浏览器运行边界
- 模块划分、数据流组织与工程化维护

该项目是我对“表达模型”与“工程实现”之间关系的一次实践，重点关注数据结构设计、模块边界与系统可扩展性。
